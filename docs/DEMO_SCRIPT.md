# Demo script

Everything shown runs locally with fictional data and AI off: `make setup && make demo`, then
open http://127.0.0.1:8000/login/. The recorded journey is in [`docs/demo/`](demo/)
(`demo-journey.webm` and three screenshots) if a live run is not possible.

## 90 seconds

| Time | Show | Say |
|---|---|---|
| 0:00 | Sign-in screen | "JournalPulse is a private journal with an optional AI companion, Luna. It's a research beta, not therapy: the 9-8-8 line is always on screen." |
| 0:10 | Press **Try the demo** | "No sign-up. This is an isolated demo account with fictional entries, and AI is switched off in code for demo identities." |
| 0:20 | Journal: write one line, **Save entry** | "Saving never touches AI. Your words are stored as written." |
| 0:35 | Talk → Simple Luna, ask for one small thing, pick an activity | "Without AI, Simple Luna is scripted. With AI, every message first passes a safety check, consent and a rate limit; risk language gets a fixed support reply and the model is never called." |
| 0:55 | Home: **Did it help?** → Helped → Calm → Save | "After an activity you say whether it helped." |
| 1:05 | Journey: "1 rating · 1 rated helpful" | "Journey shows what helped over time." |
| 1:15 | README results block | "The numbers in the README are generated by `make eval`: 1,436 backend tests at 92% coverage, and the safety router's 29 of 34 development cases, labelled as not held out. CI fails if they drop." |

## Five-minute outline

1. **The person and the promise (0:45).** Who it is for, what it is not, the 9-8-8 line.
   [CASE_STUDY.md](CASE_STUDY.md) sections 1 and 2.
2. **The journey (1:30).** The 90-second path above, slower: point out the demo banner, that
   unsaved text survives a refresh, and that the activity came from a reviewed catalog.
3. **The gates before the model (1:00).** Open `src/journalpulse/conversations.py` at
   `_take_turn` and walk the order: ownership, stale-turn checks, `assess_safety`, consent, rate
   limit, provider. Mention the limit: an English phrase list ([WALKTHROUGH Q2](WALKTHROUGH.md)).
4. **What the measurements say, including the uncomfortable part (1:00).** The 60-scenario benchmark
   beat its targets but the interval includes zero and one chest-pain case was "uncertain", so the
   release was held ([WALKTHROUGH Q4](WALKTHROUGH.md)).
5. **Operating it (0:45).** `make onboard NAME=demo` builds and checks a whole environment in about
   a minute ([report](../outputs/onboarding/first-run/REPORT.md)); the database-outage drill
   refused a write with 503, stored nothing, and the retry stored exactly one entry
   ([INCIDENT_DRILL.md](INCIDENT_DRILL.md)). The hourly check and SLO start once merged.

Questions to expect: "What happens if the model is down?" (Simple mode, 503 with nothing saved),
"Can I see someone else's entry?" (404, and row-level security again in the database), "Why
should I trust the safety numbers?" (you shouldn't yet; they are development numbers, labelled so).
