telemetry, event collector, contact database, task adapter or automatic enrollment
is added. AC-OBS-01 is NOT_APPLICABLE for this declared scope. Missing manual
observations remain unknown. Do not infer abandonment from silence. Existing

## Files and operating sequence

1. Complete the candidate/gate fields in `SESSION_TEMPLATE.json`; do not invite
   participants to test blocked capabilities. Record the exact build on each task.
2. Use `CONSENT.md` and `MODERATOR.md`. Start with five consenting English-speaking
   adults. Keep contact mapping and actual notes in restricted storage outside Git,
   screenshots, model inputs and public case studies. Assign pseudonymous P01–P05
   only after actual enrollment; blank templates are not participant records.
3. Give the tasks without click-by-click coaching. Log the first attempt under
   its time cap, assistance, duration and result. Keep retests separate. Preserve
   negative observations and actual exposure to AI, Simple or search.
4. Reconcile the first-use gates: 5/5 unassisted save/retrieve; >=4/5 unassisted
   chosen-mode reflection/action; all five ultimately distinguish data erasure
   and closure and complete the designated disposable-data task. Report initial
   assisted/unassisted results separately. An action decline is valid but does
   not count as completing action selection. Two participants with the same
   navigation confusion trigger a repair/retest before expansion.
5. Invite fresh voluntary pilot enrollment separately from session consent. Lock
   the same five-person decision cohort before observation. Record each real
   start/end in UTC, timezone, build/capabilities, withdrawal and completeness.
   Each participant's window is exactly 168 hours; day numbers are 24-hour blocks.
6. Use the PRD §11 metric definitions verbatim. The primary decision is whether
   three of the same five enrolled people have both a specific useful outcome
   and an eligible later-day return, with no unresolved P0 incident. Fewer than
   five enrollments is an incomplete cohort. Missing evidence that could change
   the decision is inconclusive. Keep counts and missingness even if three meet it.
7. At cohort close reconcile actual enrollment, mature/partial windows, opt-outs,
   zero activity, unknown observations, Simple/AI mode, modern versus legacy
   activity paths, and support incidents. Do not pool timer expiry with reports.

## Withdrawal, retention and incident procedure

At consent, assign a private owner and record the cohort-close date and deletion
deadline. Contact mapping is stored separately, encrypted/access restricted to
that owner. Do not record journal text, action titles, mood, passwords, tokens,
IP addresses or private screenshots. Optional specific usefulness notes belong
only in the restricted feedback record, never an event payload.

Check the private withdrawal inbox at least twice each day during collection.
On withdrawal: stop collection immediately; identify the person's pseudonym;
remove linked observations, optional feedback and mapping within 24 hours;
record only a content-free deletion receipt; recompute summaries and denominators.
Delete raw notes and mappings no later than 30 days after cohort close. Set a
private operator reminder when the actual close date is known. No automation is
claimed. Before enrollment, rehearse this procedure with fictional notes and a
controlled clock; real operating completion remains NOT_RUN until performed.

Use `RETENTION_REHEARSAL.md` for a bounded manual test. Record completion times
privately. If the retention owner cannot meet these obligations, do not enroll.

Stop expansion for cross-owner disclosure, loss of a confirmed save, deletion
resurrection, severe routing failure or another unresolved P0 incident. Preserve
content-free request/build identifiers, gate the affected capability, follow the
release runbook and contact the operator. Do not include private content in issue
reports. A participant may stop without explanation; never pressure AI use or a
positive rating. No therapeutic, representative-population or causal claims.

## Discovery and integration decision

Ask about the last real reflection/action attempt, current workaround, where
momentum stopped, what the person would not share, and one desired outcome.
Observe tasks before suggesting functionality. G6a is DEFERRED: no actual
participant discovery, destination selection, account feasibility or bounded
scope approval exists. Do not implement or enable external task writes.
